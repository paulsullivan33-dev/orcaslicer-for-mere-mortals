# Your First Slice

**Outcome:** one model, sliced, with the
output file on disk and its summary read.

**Check:** the output folder holds
`plate_1.gcode`, and the run's `result.json`
says `"error_string": "Success."`.
Both are shown below from the lab's real run.

> The lab ran the command-line half of
> this chapter for real. The window half
> is the standard OrcaSlicer workflow,
> described from the project's
> documentation; the lab's sandbox
> had no display to open it on.

## The model

The lab used a 20 × 20 × 20 mm cube,
generated by `orcaslicer-lab/make_models.py`
— a calibration-cube stand-in with no
features to hide behind.
Any simple model works for a first slice:
a cube shows size, walls and infill
with nothing else in the way.
Chapter 2 showed `--info` confirming
the cube is exactly 20 mm and watertight.

## In the window

1. Open OrcaSlicer. In the left panel,
   set the three dropdowns: your printer,
   a process preset, a filament.
2. Add the model file (drag it onto
   the plate, or use the add icon).
   It lands centred on the plate.
3. Look at it. Rotate the view.
   The checks that matter: it sits flat
   on the plate, it is the size you
   expect (the size readouts say
   20 × 20 × 20 mm for the cube),
   and it is not floating or sunk.
4. Press **Slice plate**.
   The view switches to the preview:
   the part rebuilt from the slice,
   with a layer slider on the right
   and the summary — time, filament
   in metres and grams — in the corner.
5. Drag the layer slider.
   Watching the walls go down,
   the infill pattern appear,
   and the top layers close over
   teaches more about slicing
   than any settings list.
6. Export the G-code file when
   you are satisfied.

## The same slice from the command line

The engine is identical; only the
driving differs. The lab's real command
(full transcript:
`orcaslicer-lab/transcripts/t02-first-slice.txt`):

```console
$ orca-slicer \
    --load-settings "…/Prusa MK3.5 0.4 nozzle.json;…/0.20mm Speed @MK3.5.json" \
    --load-filaments "…/Prusa Generic PLA @MK3.5.json" \
    --outputdir out-cube \
    --slice 0 \
    models/cube.stl
```

(The `…` stands for the profile folders
inside the extracted AppImage;
the transcript shows the full paths.)
Success is silent on the console.
The verdict lives in the output folder:

```text
out-cube/
  plate_1.gcode     the slice itself, 335447 bytes
  result.json       the run's verdict
```

```json
"error_string": "Success.",
"return_code": 0,
```

`result.json` is a gift for scripts:
a program can slice ten models
and read ten verdicts without
scraping console text. Chapter 10
uses exactly that.

## What you should see

For the cube, on the lab's preset trio:

- **100 layers.** The cube is 20 mm tall
  and this process preset prints every
  layer, the first included, at 0.20 mm:
  100 × 0.20 = 20.0 mm exactly.
  (The layer markers in the file read
  Z 0.2, 0.4, 0.6 … up to 20.0.)
- **Time estimate:** 46 m 34 s,
  of which the footer attributes
  21 m 47 s to the first layer —
  this preset prints its first layer
  slowly, on purpose, for adhesion.
- **Filament:** about 1.34 m,
  3.23 cm³ of plastic.
  The footer says `0.00 g` for weight —
  not a bug in your reading:
  this filament preset carries
  a density of 0, so grams cannot
  be computed. Chapter 13 lists it
  as a known trap.

Hold on, though.
Everything in that list is the slicer
*describing its own work*.
Estimates can be wrong; summaries
can be misread. The next chapter
checks the same claims against
the file itself.

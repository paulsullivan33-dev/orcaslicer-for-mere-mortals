# Writing Criteria

Every guide in this series is built to the same rules.
Here is the standard this guide was written against,
and the notes on where it stands.

## 1. General audiences only

Every example is safe to show a stranger:
test models the lab generated itself,
generic printer families,
placeholder values only.
Nothing is modelled on a real person,
household, organisation, network,
or printer the author owns.
Chapter rule: chapter 1 states what
a slicer is in one sentence a newcomer
can repeat.
*Standing: met.*

## 2. Reader-first structure

Chapters open with the outcome and a check
the reader can run:
a help text, a counted layer number,
a summed extrusion total.
Commands are copyable and produce the
stated output, because the lab ran them
and transcribed what came back.
*Standing: met for every command-line step;
window steps carry the documented-only label instead.*

## 3. Local-first tasks

Slicing happens on the reader's machine.
Nothing in the core workflow needs an
account, a cloud, or a network.
Cloud print services are described once,
in chapter 9, as an option with its price
named (an account, and print metadata
leaving the house), never as the path.
*Standing: met.*

## 4. Real verification

The core tasks ran for real in the lab;
see **The Lab** below.
Success criteria are observable:
`result.json` verdicts, layer counts
checked three independent ways,
extrusion totals summed from the file's
own moves and compared with the slicer's
footer. "It sliced" was never the bar —
"the file proves it" was.
*Standing: met, with the multicolor exception
documented in full rather than smoothed over.*

## 5. Honest failures

Named plainly, with the error text the
program printed.

- Bundled Creality and Prusa XL preset trios
  refuse command-line slicing (error −51):
  raw profile files load without part of
  their inherited values, and the slicer's
  own extruder-reset check refuses.
  The chapter 13 copy-and-patch fix is
  verified for the XL; the general gap
  is reported, not hidden.
- A two-filament slice does not apply
  the second filament from the command
  line, across four attempts and two
  machine families (full evidence in
  transcript t05). The multicolor
  chapter is labelled documented-only
  because of it.
- The AMF route misreads geometry
  (zero volume) in this release.
*Standing: met.*

## 6. Code-level criteria

The `orcaslicer-lab` folder holds the lab:
model generators, the G-code checking
script, the patched process preset,
and transcripts. The checker reads a
G-code file and independently recounts
layers and extrusion; it is plain
standard-library Python,
`python3 orcaslicer-lab/check_gcode.py FILE.gcode`.
Nothing in the guide depends on code
the reader cannot read.
*Standing: met.*

## 7. Limits in the text, not the fine print

One Limits chapter (chapter 12):
no window run in the lab, no printer
involved, one release tested,
the command-line multicolor limit,
estimates versus file truth.
Failure modes are collected in
Troubleshooting with the fixes
that are verified and the ones
that are not.
*Standing: met.*

## 8. The safety rule in the text early

G-code is instructions to a machine
that heats and moves. Chapter 1 and
the home page both state the rule
before any task: slice for the printer
in front of you, read the file before
it prints, check the machine preset
matches the physical machine.
Nothing in the guide encourages
printing an unread file.
*Standing: met.*

## 9. Series voice

Plain language. Short sentences.
Each chapter stands on one idea:
a slicer is a compiler; presets are
diffs; the file testifies about itself.
Instructions do what they say,
counts are real counts,
and the reader finishes knowing
how to doubt a summary productively.
*Standing: met.*

## The Lab

**What the lab machine was:**
an Ubuntu 24.04 sandbox VM,
no display, no printer,
package installs unavailable
(the apt lock was held by another tenant).

**What ran for real:**

- The official OrcaSlicer 2.4.2
  Ubuntu 24.04 AppImage
  (SHA-256 d12fb8c8…fd82880f029fd),
  extracted with `--appimage-extract`;
  the host GUI libraries it links were
  supplied from extracted `.deb`
  packages via `LD_LIBRARY_PATH`
  (transcript t00).
- Test models generated by
  `orcaslicer-lab/make_models.py`
  (20 mm cube; two 10 × 10 × 6 mm bars)
  and inspected with `--info`
  (transcript t01).
- The cube sliced from the command line
  with a bundled Prusa MK3.5 machine /
  process / filament trio:
  `plate_1.gcode` produced,
  `result.json` verdict Success
  (transcript t02).
- The G-code proved with
  `orcaslicer-lab/check_gcode.py`:
  100 layers by markers, by distinct
  extrusion heights, and by the footer;
  net extrusion 1321.7 mm summed from
  the moves against the footer's
  1341.47 mm (about 1.5% apart);
  path-type table counted
  (transcript t03).
- A layer-height experiment: a copy of
  the process preset with
  `"layer_height": "0.12"` produced
  166 layers and a 1 h 1 m estimate
  against 100 layers / 46 m 34 s
  (transcript t04).
- Four multicolor attempts
  (Bambu A1 and Prusa XL profiles,
  filament ids both ways, an edited
  project file, an AMF model) —
  all sliced single-filament;
  the resolved-settings dump, the
  project file's object records,
  and the byte-level comparison
  are in transcript t05.
- The failures: error −51 on two
  bundled trios (and the verified
  process-copy fix), error −3 for
  missing preset and model files,
  error −102 for corner placement
  and its centring fix
  (transcript t06).

**Documented-only (not run):**
the graphical window and everything
done in it (first-launch setup,
slicing by button, painting and
per-object filament assignment,
sending to hosts);
multicolor workflow and printing
generally;
printer-specific profiles beyond
the bundled files the lab loaded;
supports (no lab model needed them);
sending prints by any route.

**To rerun the core checks:**
extract the same AppImage, run the
slice command in transcript t02,
then the checker on the output.
Every number in chapters 5–7
should reproduce exactly,
except timestamps.

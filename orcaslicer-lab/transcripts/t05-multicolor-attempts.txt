MULTICOLOR FROM THE COMMAND LINE - four genuine attempts, none produced
a two-filament print in OrcaSlicer 2.4.2. This transcript is the evidence
behind the multicolor chapter being labelled documented-only.

The model: two 10 x 10 x 6 mm bars side by side (make_models.py), meant
to print as one 20 x 10 x 6 mm block, left half filament 1, right half
filament 2 - a tool change on nearly every layer.

ATTEMPT 1 - Bambu Lab A1 (AMS, single nozzle), two different PLA presets,
--load-filament-ids "1,2", bars loaded as two STL files.
The slice completed and wrote plate_1.gcode, but:
; total layer number: 30
; filament: 1
$ grep -c "^T1$" out-multi2/plate_1.gcode
0
Dumping the resolved settings (--export-settings) showed why: both preset
names loaded, but the per-filament value arrays collapsed to one entry:
  filament_settings_id = ["Generic PLA @BBL A1", "Bambu PLA Basic @BBL A1"]
  filament_colour      = ["#F2754E"]        <- one entry
  nozzle_temperature   = ["200"]           <- one entry

ATTEMPT 2 - Prusa XL (five toolheads), two PLA presets, filament ids
tried as both "1,2" and "0,1". Identical outcome: both objects sliced
with extruder 1, no tool-select commands in the G-code:
; filament: 1
; filament used [mm] = 310.94
; filament used [cm3] = 0.75
$ grep -cE "^T[01]" out-multi-xl2/plate_1.gcode
0
(The XL run first needed the layer-reset fix from t06/failure 1 applied
to a copy of its process preset - see orcaslicer-lab/xl-process-g92.json.)

ATTEMPT 3 - export a project file and edit the assignment inside it.
$ orca-slicer ... --export-3mf bars-xl.3mf
Metadata/model_settings.config inside the exported 3MF records what the
CLI actually applied - both objects at extruder 1, the filament-ids
option never landed:
    <metadata key="extruder" value="1"/>     (object 2, bar-a-xl.stl)
    <metadata key="extruder" value="1"/>     (object 4, bar-b-xl.stl)
Editing object 4 (bar-b) to extruder 2, re-zipping and slicing the 3MF
gave G-code identical to the unedited project except for the timestamp:
$ md5sum out-multi-orig/plate_1.gcode out-multi-final/plate_1.gcode
7015fcfd0e9a75b1c2e2c0a1f612d6ff  out-multi-orig/plate_1.gcode
0ecc953c5e01b8cab934745dc5e89000  out-multi-final/plate_1.gcode
(the md5s differ only because the "; generated by" line carries the time;
a diff with that line removed is empty.)

ATTEMPT 4 - an AMF file with two materials, the older interchange route
for multi-material models. OrcaSlicer --info misread the geometry:
  size_x = 0.000000   volume = 0.000000   manifold = no   (per object)
so that route is not usable in this build either.

CONCLUSION: in 2.4.2 the per-object filament assignment is, in practice,
a GUI operation. The CLI slices one filament per plate reliably; the
multicolor chapter therefore teaches the GUI workflow (painting and
per-object assignment) as documented-only, from the OrcaSlicer wiki, and
quotes the AMS tool-change script from the A1 profile config block that
the lab did read in full (out-multi2/plate_1.gcode, CONFIG_BLOCK).
